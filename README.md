# Reference_Agent

基于 arXiv 和智谱 AI 的命令行文献引用核查工具。

读取 Word 文档中的参考文献和引用标记，统计引用情况，自动检索并下载 arXiv 论文，再使用大语言模型判断引文是否得到对应论文内容的支持。

> 当前版本为原型工具。核查结果供人工复核参考，不能作为引用准确性的最终结论。

## 功能

- **引用情况检查**：统计识别到的参考文献数量，提示未被引用的文献，以及出现多次的引用编号。
- **论文检索与下载**：使用参考文献标题搜索 arXiv，下载标题匹配的论文 PDF。
- **引文内容核查**：提取引用所在句子和对应 PDF 全文，调用智谱 AI 判断引用是否准确。
- **终端结果输出**：显示核查进度、跳过的引文、模型给出的错误原因和最终错误计数。

## 工作流程

```text
读取 .docx 文档
    ↓
提取参考文献标题及引用标记
    ↓
统计未引用和重复引用情况
    ↓
从 arXiv 检索并下载论文 PDF
    ↓
提取引用所在句子与论文全文
    ↓
调用智谱 AI 核查并输出结果
```

## 环境要求

- Python 3.12 或更高版本
- uv，或使用 pip 管理依赖
- 可用的智谱 AI API Key
- 能够访问 arXiv 和智谱 AI 服务的网络环境

核心依赖：

| 依赖 | 用途 |
| --- | --- |
| `python-docx` | 读取 Word 文档段落 |
| `arxiv` | 检索并下载 arXiv 论文 |
| `pymupdf` | 提取 PDF 文本 |
| `zhipuai` | 调用智谱 AI |
| `python-dotenv` | 加载 `.env` 环境变量 |

项目还声明了 `gradio` 和 `openai` 依赖，但当前运行入口使用命令行和智谱 AI SDK，尚未实现 Web 界面或 OpenAI 调用流程。

## 快速开始

### 1. 获取项目并安装依赖

```bash
git clone https://github.com/kyk666123/Reference_Agent.git
cd Reference_Agent/reference_agent

uv sync --locked
```

以下步骤均从 `Reference_Agent/reference_agent` 目录开始。

### 2. 配置 API Key

在当前目录创建 `.env` 文件：

```dotenv
ZHIPUAI_API_KEY=你的智谱AI_API_Key
```

程序启动时会通过 `load_dotenv()` 加载环境变量。

请勿将真实 API Key 提交到仓库。

### 3. 准备待检查文档

创建输入文档和参考论文目录：

```bash
mkdir -p data/docs data/references
```

将待检查的 Word 文档放入：

```text
data/docs/kyk_report.docx
```

文件名可以修改，运行时通过 `--doc` 指定实际路径。仓库目前未提供该示例文档，需要自行准备。

### 4. 运行核查

进入示例目录并执行：

```bash
cd examples

uv run --project .. ../reference_agent/agent.py \
  --model glm-4-flash \
  --prompt ../reference_agent/prompts/agent_prompt \
  --doc ../data/docs/kyk_report.docx \
  --ref ../data/references
```

`glm-4-flash` 是仓库示例使用的模型名称。请根据账号实际可用模型调整 `--model`。

> 请按上述步骤从 `examples` 目录运行。当前下载代码将 PDF 固定保存到相对于工作目录的 `../data/references`，并不会使用 `--ref` 参数决定下载位置。保持 `--ref` 与下载目录一致，才能正确读取论文。

### 使用 pip 安装

如果不使用 uv，可在 `Reference_Agent/reference_agent` 目录创建虚拟环境并安装依赖：

```bash
python3 -m venv .venv
source .venv/bin/activate

python -m pip install \
  "arxiv>=2.2.0" \
  "gradio>=5.25.0" \
  "openai>=1.72.0" \
  "pymupdf>=1.25.5" \
  "python-docx>=1.1.2" \
  "python-dotenv>=1.1.0" \
  "zhipuai>=2.1.5.20250106"
```

然后完成上述 API Key 和文档准备步骤，从 `examples` 目录运行：

```bash
cd examples

python ../reference_agent/agent.py \
  --model glm-4-flash \
  --prompt ../reference_agent/prompts/agent_prompt \
  --doc ../data/docs/kyk_report.docx \
  --ref ../data/references
```

Windows 用户请使用对应的虚拟环境激活命令。

## 输入文档格式

当前解析逻辑依赖固定格式，建议先使用少量引用验证文档能否正确识别。

### 文档类型

输入必须是 `.docx` 文件。程序读取普通段落文本，目前不处理表格、脚注、尾注或图片中的引用。

### 参考文献标题

文档中必须存在一个独立段落，内容准确为：

```text
参考文献
```

请避免添加编号、前后空格或其他文字。程序将该段落之后的内容作为参考文献列表解析。

### 参考文献条目

每篇参考文献建议单独占一个段落，采用以下形式：

```text
作者. 论文标题[J]. 期刊或其他出版信息.
```

示例：

```text
Vaswani A, et al. Attention Is All You Need[J]. 2017.
```

当前程序从英文句点 `.` 之后、文献类型标记之前提取标题。类型标记需为单个大写字母，例如 `[J]`、`[C]`。

注意：

- 标题内的英文句点可能影响解析。
- 不符合格式的条目可能被忽略。
- 文献编号按成功提取到的标题顺序，从 1 开始分配。
- 程序不会直接读取条目中的显式编号来建立对应关系。

### 正文引用

支持以下引用标记：

```text
[1]
[1,2]
[1, 2, 3]
```

例如：

```text
该方法通过注意力机制建模序列之间的关系[1]。
```

暂不支持：

```text
[1-3]
[1，2]
（作者，年份）
```

引用所在句子的边界按中文句号 `。` 提取，因此更适合采用中文句号分句的文档。

> 当前程序扫描所有段落中的引用标记，包括参考文献部分。如果参考文献条目本身带有 `[1]` 等编号，这些编号也会被计入引用统计，可能使未引用检查或重复引用提示产生偏差。

## 命令行参数

所有参数均为必填项。

| 参数 | 含义 | 示例 |
| --- | --- | --- |
| `--model` | 智谱 AI 模型名称 | `glm-4-flash` |
| `--prompt` | 提示词文件路径 | `../reference_agent/prompts/agent_prompt` |
| `--doc` | 待检查的 Word 文档路径 | `../data/docs/kyk_report.docx` |
| `--ref` | 核查时读取 PDF 的目录 | `../data/references` |

所有相对路径均相对于执行命令时的工作目录。

## PDF 文件规则

论文以引用编号命名：

```text
data/references/
├── 1.pdf
├── 2.pdf
└── 3.pdf
```

如果某篇论文无法从 arXiv 自动下载，可以自行获取 PDF，并按文档中的对应编号放入该目录。程序仍会执行检索步骤，但核查阶段会读取目录中已有的文件。

建议为每份待检查文档使用干净的参考论文目录，避免旧文件与当前文献编号错配。目录中只保留以数字命名的 PDF 文件，例如 `1.pdf`，不要放入 `.DS_Store` 或其他非数字文件名的文件。

## 输出说明

程序依次执行三个阶段：

1. 核查引文数量及引用情况。
2. 检索并下载论文。
3. 核查引文与论文的对应关系。

终端输出示例：

```text
第1步: 核查引文数量及引用情况
文献列表共有3篇参考文献
文献[2]没有被引用
文献[1]的引用超过1次,共引用了2次
------------分割线-------------
第2步: 开始下载文献:
...
------------分割线-------------
第3步: 核查引文与文献的对应关系
引文[1]核查无误
...
```

当某条引文涉及的 PDF 不齐全时，程序跳过整条引文的内容核查。

当前结果仅输出到终端，不会修改原 Word 文档，也不会自动生成独立报告文件。

## 自定义提示词

默认提示词位于：

```text
reference_agent/reference_agent/prompts/agent_prompt
```

提示词中需要保留两个 `{}` 占位符，依次接收：

1. 引用所在句子。
2. 对应论文的 PDF 提取全文。

默认要求模型返回：

```text
<是>
```

或者：

```text
<否: '错误原因'>
```

当前代码仅将完全等于 `<是>` 的回复识别为核查通过，将包含 `否` 的回复计入错误。其他格式的回复可能不会被明确记录，因此修改提示词时应保留上述返回约定。

## 当前限制

- **检索范围有限**：仅检索 arXiv，每个标题最多查看 5 条结果；只有标题忽略大小写后完全一致才自动下载。
- **文档格式要求严格**：参考文献标题、条目格式和引用标记均依赖固定解析规则。
- **重复引用不代表错误**：重复引用提示只反映标记出现次数，同一篇论文被引用多次通常是合理情况。
- **无 OCR**：扫描版 PDF 或缺少文本层的 PDF 可能无法提取有效内容。
- **上下文长度有限**：程序将对应论文全文直接发送给模型，尚未实现分块、检索或上下文截断。
- **缺少异常恢复**：网络故障、API 错误、无效 PDF 或目录问题可能中断运行，目前没有自动重试。
- **统计口径有限**：最终错误计数来自模型判为“否”的核查记录，不等同于去重后的错误论文数量。
- **模型结果需要复核**：模型可能误判；当前也没有输出支持判断的论文页码或原文证据。

## 常见问题

### 提示找不到“参考文献”

确认 Word 中有一个独立段落，内容准确为 `参考文献`，且没有前后空格、编号或其他文字。

### 识别到的参考文献数量少于实际数量

检查每条参考文献是否单独成段，并符合 `作者. 标题[J]. ...` 的结构。无法匹配的条目不会加入标题列表。

### arXiv 未找到论文

论文可能未收录于 arXiv，或标题与检索结果不完全一致。可以手动将正确 PDF 保存为对应编号，例如 `2.pdf`。

### 下载成功后仍无法核查

确认从 `examples` 目录运行，并使用 `--ref ../data/references`。当前 PDF 下载目录固定，不随 `--ref` 改变。

### 出现文件名转整数错误

检查参考论文目录是否包含非数字文件名的文件。程序会尝试将目录内每个普通文件的文件名主体转换为整数。

### API 调用失败

检查 `ZHIPUAI_API_KEY` 是否正确加载、所选模型是否可用，以及网络连接和账号额度。

## 数据使用说明

核查时，引用所在句子和对应论文的提取全文会发送至智谱 AI 服务。使用前请确认相关内容适合提交到该服务，并遵守文档保密要求和论文使用条款。
